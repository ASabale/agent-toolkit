# Runner and chains

On 2026-11-03, `ASabale/agent-toolkit@9d469d7` added `lib/runner.py` (472 lines in that commit) and the `tk` entrypoint (421 lines). `CODING_STANDARDS.md` at the same commit named the runner the validation, execution, and chaining seam. Public functions were `parse_cli_flags`, `validate_and_build_env`, `run_tool`, and `run_chain`.

## Flag grammar

On 2026-11-03, `parse_cli_flags` at `ASabale/agent-toolkit@9d469d7` accepted `--dry-run` anywhere in argv, `--flag value`, `--flag=value`, and a bare `--flag` (stored as `"true"`). Tokens that did not start with `--` became positional. This matched the order-independent flag rule written the same day in `AGENTS.md` at `ASabale/agent-toolkit@d4c16aa`. See [0002](../decisions/0002-minimum-cognitive-load-and-tokens.md). *(Superseded on 2026-11-04 by `ASabale/agent-toolkit@46a6538`, which added an optional `item` parameter to `parse_cli_flags(argv, item=None)`: when `item` was supplied, boolean flags only consumed a following boolean literal token rather than swallowing positional arguments, and non-boolean flags accepted values starting with `-` or `--` other than `--dry-run`.)*

On 2026-11-03, `validate_and_build_env` rejected a non-empty positional list with `positional_arguments_forbidden` and `fix` set to the item example. Unknown flags produced `unknown_flag`. Missing required flags produced `missing_required` and a `fix` command that kept already accepted flags and appended `--missing <value>` placeholders. Types were checked as int (no `.`, `e`, or `E`), finite float, bool (`true`/`1`/`yes`/`false`/`0`/`no`), or string. Success returned env `TK_DRY_RUN` of `1` or `0` and `TK_ARG_<NAME>` values, including defaults for omitted optional flags.

## Execution

On 2026-11-03, `run_tool` validated flags, executed `item["path"]`, and required stdout to be compact JSON. Failures became a single-line JSON object on stderr with `error`, `why`, and `fix`. An unexpected exception became `internal_error` with `fix` `tk check`, matching the trust invariant in [0003](../decisions/0003-autonomous-chief-of-staff-governance.md).

On 2026-11-04, `ASabale/agent-toolkit@3619bfa` set `TK_ROOT_DIR` to the toolkit root on the environment `run_tool` copies from `os.environ`, and started the tool with `cwd=None`, so the process keeps the caller's working directory. Relative flag values such as `--path` and `--repo` resolve there. `ASabale/agent-toolkit@eb1d6ca` stopped prepending the toolkit root to `PYTHONPATH`; the caller's `PYTHONPATH` is not modified. Tools import `lib` by inserting the toolkit root on `sys.path` from `__file__`, the same way `tk` and `tools/.template` do. `lib/catalog.py` `_dry_run_error` runs every `tk check` dry-run, including read-only tools, with `cwd` set to a fresh `tempfile.TemporaryDirectory()`. `HOME` is replaced with that directory only when safety is `mutating` or `destructive`.

On 2026-11-03, `_record_run` skipped logging when `dry_run` was true. A real exit 0 logged `run_ok`. A real non-zero exit logged `run_error` with `why` taken from stderr JSON when that JSON had a `why` string. See [Evolver and quarantine](evolver-and-quarantine.md).

## Chains

On 2026-11-03, `ARCHITECTURE.md` at `ASabale/agent-toolkit@4b0e69c` specified saved chains as `chains/<name>.json` and said a saved chain appears in `tk find` like an atomic tool. `ASabale/agent-toolkit@d4c16aa` kept that composition section while shortening the skill's chaining instructions.

On 2026-11-03, `run_chain` at `ASabale/agent-toolkit@9d469d7` validated chain-level flags, then for each step resolved `$input.<arg>`, `$prev.<path>`, and `$step[i].<path>` into the next tool's flags. Each step's JSON stdout became the next step's previous value. The first error stopped the pipeline (`unknown_tool`, `unresolved_reference`, `invalid_chain`, or the failing tool's own error). `tk run <chain-name>` and `tk chain run <name>` both reached this function. `tk` passed `chains_only=True` for the `chain run` path.

On 2026-11-03, `chains/git.repo-health.json` at `ASabale/agent-toolkit@9d469d7` named `git.repo-health`, safety `read-only`, one required `--repo` string, and two steps: `git.branch-digest` with `repo: "$input.repo"`, then `json.pick` with `keys: "branch,ahead,behind,dirty,detached,upstream"`. Its example was `tk run git.repo-health --repo .` and its `verified` field was `none`.

On 2026-11-04, `ASabale/agent-toolkit@c37e045` updated `parse_cli_flags` in `lib/runner.py` so `--dry-run=0|false|no|off` evaluated to `dry_run=False`, added `TK_TIMEOUT` (default 60s) subprocess timeout protection in `run_tool` returning `error="tool_timeout"`, added `--arg`, `--example`, and `--force` flags to `tk chain save`, and added `chains/gh.triage-pr.json` (`gh.pr-failure-digest` piped into `json.pick` with `keys: "repo,pr,fail,pending,checks"`). Later on 2026-11-04, `ASabale/agent-toolkit@b7f9668` updated `validate_and_build_env` in `lib/runner.py` to suggest the closest declared flag (or single missing required flag) and rewrite `fix` with the caller's supplied value, enforced `TK_MAX_OUTPUT_BYTES` (default 65,536 bytes, returning `error="output_too_large"`), and updated `tools/py/test-digest` to strip `TK_*` environment variables before spawning child `unittest` runs. Later on 2026-11-04, `ASabale/agent-toolkit@9fe185e` updated `_resolve_expr` and `run_chain` in `lib/runner.py` to resolve whole-object `$prev` and `$step[i]` references, fall back to synthetic typed values under `dry_run=True` when an upstream dry-run payload omitted a nested field, safely default malformed `TK_TIMEOUT` / `TK_MAX_OUTPUT_BYTES` environment values, and added `chains/git.repo-audit.json` (`git.log-recent` piped into `json.query` with `expr: "commits[*].{sha,subject}"`).

On 2026-11-04, `ASabale/agent-toolkit@a43a2d0` (`ASabale/agent-toolkit/pull/112`) changed that `run_tool` timeout path: each tool started in its own session (`start_new_session=True`); on timeout it sent SIGTERM to the whole process group, then SIGKILL after a 0.2s grace, so descendants such as `sleep` did not survive; and the `tool_timeout` `fix` became `TK_TIMEOUT=<2x current> tk run <tool> <supplied flags>` instead of the tool's example (for example `TK_TIMEOUT=1.2 tk run py.test-digest --path <dir>` after a 0.6s timeout).

On 2026-11-04, pull request #38 updated `run_tool` so an object stdout with integer `truncated > 0` from a tool that declares `--limit` gains a copy-pasteable `next` command (same invocation, `--limit` doubled and capped). The same change made `output_too_large.fix` a real command: `--limit` halved when declared, otherwise `TK_MAX_OUTPUT_BYTES=<observed size> tk run … | tk run json.pick --keys <subset>` so the producer can emit and `json.pick` reduces under the original cap.

Catalog lookup for those step names went through `discover_catalog`. See [Catalog and check](catalog-and-check.md).

On 2026-11-04, `ASabale/agent-toolkit@7001f67` deleted `chains/sec.repo-hygiene.json`. That chain had run `sec.secret-scan` and then `json.pick` with keys `clean,count,findings`, which dropped `truncated`. `sec.secret-scan` remained and still reports `truncated`. This supersedes the chain's presence at `ASabale/agent-toolkit@5a57fcd` and `ASabale/agent-toolkit@5aece9a` without rewriting those claims.

On 2026-11-04, `ASabale/agent-toolkit@98bb7ac` deleted `chains/git.repo-health.json`, `chains/sql.inspect-db.json`, `chains/code.module-surface.json`, and `chains/code.blast-radius.json`. Each chain was one tool (`git.branch-digest`, `sql.schema`, `code.symbols`, or `code.dependents`) followed by `json.pick` and did not collapse a multi-tool workflow. Those four tools remain. This supersedes the `git.repo-health` description at `ASabale/agent-toolkit@9d469d7` without rewriting that claim. The same commit reports a pick-all-keys chain from `tk evolve --no-promote` under `overlap_candidates` with reason `no_op_chain`; see [Evolver and quarantine](evolver-and-quarantine.md).

On 2026-11-04, `ASabale/agent-toolkit@ad02745` deleted `chains/gh.pr-overview.json`. That chain had run `gh.pr-diff-digest` and then `json.pick` with keys `repo,pr,title,state,files_changed,additions,deletions,files`, which dropped `truncated`, and it rejected `--limit`. `gh.pr-diff-digest` remains and still reports `truncated`. This supersedes the chain's presence at `ASabale/agent-toolkit@5aece9a` without rewriting that claim.

On 2026-11-04, `ASabale/agent-toolkit@5a57fcd` added `tk find [query] [--namespace <ns>]`. `--namespace <ns>` and `--namespace=<ns>` set the filter. A missing or blank value exited 2 with `error` `missing_flag` and `why` `--namespace requires a value`. `find_items` stripped that value, lowercased it, and removed trailing dots. A non-empty namespace kept items whose lowercased name equaled the namespace or started with `<namespace>.`. Token scoring ran after the filter. With no `--limit`, the ranked list was not capped. A zero-match call logged `search_miss` and wrote empty stdout, and did not write a stderr `no_match` object. *(Superseded in part on 2026-11-04 by `ASabale/agent-toolkit@75361b1`: a non-empty query defaults to 5 items, and a zero-match non-empty query writes one stderr JSON line `{"error":"no_match",...}` with `fix` `tk find --namespace <ns>` when the first query token is an existing namespace. The namespace match rule is the `5a57fcd` rule.)*
