# Evolver and quarantine

On 2026-11-03, `ASabale/agent-toolkit@9d469d7` added `lib/evolver.py` (921 lines in that commit). The module docstring named three public behaviors: `log_event` (append-only telemetry that does not raise), `save_tool` / `save_chain` (write a draft, validate with `check_item`, roll back on failure), and `evolve_report` (promote read-only tools that pass check, and summarize friction). `CODING_STANDARDS.md` at the same commit described that seam and did not define `prune_tools`. `tk` at the same commit exposed `tk evolve [--no-promote]` and did not expose `tk prune`. See [0003](../decisions/0003-autonomous-chief-of-staff-governance.md).

## Telemetry

On 2026-11-03, `log_event` created `state/`, appended one compact JSON object to `state/events.jsonl` with `ts` (UTC ISO timestamp) and `event`, copied payload keys other than `ts` and `event`, and returned on any exception. *(Superseded on 2026-11-04 by `ASabale/agent-toolkit@b7f9668`, which added `TK_STATE_DIR` to relocate `events.jsonl`, `quarantine/`, and `archive/`, and `TK_NO_TELEMETRY=1|true|yes` to skip telemetry writes during pre-commit hooks and CI. On 2026-11-04 the pre-commit gate moved to the tracked `.githooks/pre-commit` and `install.sh` sets `git config core.hooksPath .githooks`; see [0003](../decisions/0003-autonomous-chief-of-staff-governance.md).)*

On 2026-11-03, `tk` logged `search_miss` from `tk find` (empty match set), from `tk info` (unknown name), and from `tk run` (unknown name). `lib/runner.py` logged `run_ok` or `run_error` only when the call was not a dry-run. See [Runner and chains](runner-and-chains.md).

On 2026-11-03, `_summarize_events` treated `run`, `run_ok`, `tool_run`, and `chain_run` as usage; `run_error` and `error` as failures; and `search_miss` and `miss` as misses. Miss queries were counted and sorted by descending count, then query text.

On 2026-11-04, `ASabale/agent-toolkit@75361b1` changed `tk find` so a non-empty query defaults to 5 items (explicit `--limit N` overrides; an empty query stays uncapped). A zero-match query still logs `search_miss`, and also writes one stderr JSON line `{"error":"no_match","why":"no tool or chain matches '<query>'","fix":"tk find"}` (`fix` is `tk find --namespace <ns>` when the first query token is an existing namespace), then exits 0 with empty stdout.

## Save and quarantine

On 2026-11-03, `save_tool` wrote `tools/<namespace>/<rest>` when the name contained a dot (`git.branch-digest` → `tools/git/branch-digest`), mode `0o755`, from either `--from-cmd` or `--file`, with a generated `# @tk-*` header. `save_chain` wrote `chains/<name>.json` with `verified: "none"`. Both went through `_commit_draft`. *(Extended on 2026-11-04 by `ASabale/agent-toolkit@5a57fcd` and `ASabale/agent-toolkit@5aece9a`, which added automatic `@tk-arg` inference from `TK_ARG_<NAME>` and `${TK_ARG_<NAME>:-default}` references in `save_tool` while preserving existing `# @tk-arg:` headers when `--file` and `--arg` were combined, and updated `_chain_candidates` to reset adjacency on `run_error` events. The inference half of that description was superseded on 2026-11-04 by `ASabale/agent-toolkit@c8cb854`: `save_tool` infers an `@tk-arg` only when the script reads the variable (`$TK_ARG_<NAME>`, `${TK_ARG_<NAME>...}`, or Python `environ` / `getenv`). A bare `TK_ARG_<NAME>` mention in a comment or string literal is ignored. `${TK_ARG_<NAME>:-default}` still infers an optional arg with that default. `tk check` uses the same read rule.)*

On 2026-11-03, `_commit_draft` refused an existing destination unless `force` was true (`already_exists`). It wrote the new text, chmod'd tools to `0o755`, and called `check_item` (the catalog implementation when importable, otherwise a fallback checker in `lib/evolver.py`). On failure it called `_quarantine`, then either deleted the new file (and removed empty parent directories up to `tools/` or `chains/`) or restored the previous bytes. The error returned to the caller was `check_failed` with the check errors joined into `why` and `fix` `tk check`. On success it logged `tool_saved` or `chain_saved` and printed compact JSON `{"ok":true,"name", "kind", "path", "safety"}` on stdout.

On 2026-11-03, `_quarantine` wrote the rejected text to `state/quarantine/<safe-filename>.<UTC-stamp>`. The stamp format was `%Y%m%dT%H%M%S%fZ`. Characters outside `[A-Za-z0-9._-]` in the filename became underscores. Quarantine I/O failures were swallowed. That directory was the rollback copy; the catalog path did not keep the invalid draft. The single-file contract those drafts had to satisfy was recorded in [0001](../decisions/0001-clean-slate-single-file-contract.md). Header checks at the same commit were recorded in [Catalog and check](catalog-and-check.md).

On 2026-11-04, `ASabale/agent-toolkit@9c0f0f6` (`ASabale/agent-toolkit/pull/79`, closes #30) changed `check_item` so a `mutating` or `destructive` tool is never executed unless a non-comment line references `TK_DRY_RUN`. Unguarded drafts fail `tk check` / `tk save` / `tk evolve` with `<safety> tool must branch on TK_DRY_RUN`, and `tk save` quarantines them. Guarded tools are smoke-run with `cwd` and `HOME` set to a fresh `tempfile.TemporaryDirectory()`, and stdout must be a JSON object `{"dry_run":true,"plan":[...]}` with a non-empty `plan`. `tk run <name> --dry-run` on an unguarded non-read-only tool returns `error="dry_run_unsupported"` without launching it. `_render_wrapped_tool` for non-read-only `tk save --from-cmd` / `--file` now prints that plan payload.

## Promotion and overlap

On 2026-11-03, `evolve_report` read the catalog and `state/events.jsonl`. For each item it ran `check_item`. Check errors and recorded `run_error` lines were listed under `failing_tools`. Names absent from the usage set were listed under `unused_tools` (the report did not delete those files). When `auto_promote` was true, a tool (not a chain) with safety `read-only`, a passing check, and `verified` empty or one of `none`, `unverified`, or `null` had its first `# @tk-verified:` line replaced with `# @tk-verified: <YYYY-MM-DD>` from `date.today()`, and the executable bits were set. `tk evolve --no-promote` passed `auto_promote=False`. An unexpected failure returned empty lists for `promoted`, `search_misses`, `failing_tools`, `unused_tools`, and `overlap_candidates`.

On 2026-11-04, `ASabale/agent-toolkit@2ed72de` changed `evolve_report` so an unverified read-only tool or chain is auto-promoted only when `check_item` passes and `state/events.jsonl` has at least one `run_ok` for that name. Check-passing items with no `run_ok` are listed under `awaiting_live_run`, including when `auto_promote` is false (`--no-promote`). This supersedes the 2026-11-03 promotion rule that promoted a passing read-only tool without a live run.

On 2026-11-03, `_overlap_candidates` tokenized each name and summary into lowercase words of length at least 3, dropped the stopword set `a`, `an`, `and`, `for`, `from`, `into`, `json`, `only`, `per`, `that`, `the`, `this`, `tool`, `tools`, `via`, `with`, `when`, `your`, and emitted a pair when the intersection had at least two tokens. `score` was the Jaccard ratio rounded to three decimals. The function did not drop pairs below a score cutoff, and it did not delete either tool. *(Superseded on 2026-11-04 by `ASabale/agent-toolkit@c37e045`, which excluded structural stopwords like `digest`, `file`, `tree`, `get`, `list`, `path`, `repo`, skipped chain-to-own-step pairs, and required Jaccard `score >= 0.35`.)*

On 2026-11-03, `chains/git.repo-health.json` still had `"verified": "none"` in `ASabale/agent-toolkit@9d469d7`. `evolve_report` promoted only `kind == "tool"`, so that chain was outside auto-promotion. *(Superseded on 2026-11-04 by `ASabale/agent-toolkit@46a6538`, which deleted the Wave-1 fallback parser duplication in `lib/evolver.py`, updated `evolve_report` to auto-promote passing `read-only` chains alongside `read-only` tools, and raised the cross-namespace overlap threshold to `0.50` while keeping same-namespace overlap at `0.35`; and extended on 2026-11-04 by `ASabale/agent-toolkit@7c9fd95`, which added `chain_candidates` to `evolve_report` to mine consecutive `run_ok` tool pairs occurring at least twice in `state/events.jsonl` that were not already the opening steps of an existing chain.)*

## Prune and archive

On 2026-11-04, `ASabale/agent-toolkit@c37e045` added `prune_tools(root_dir, names, dry_run=False)` in `lib/evolver.py` and `tk prune [<name> ...] [--unused] [--dry-run]` in `./tk` (superseding the `9d469d7` omission noted in the opening paragraph). When an active chain not in `names` referenced a target tool, `prune_tools` returned exit code `2` with `error="tool_in_use_by_chain"`. Otherwise it moved pruned items to `state/archive/<UTC-timestamp>-<name>`, removed empty parent directories under `tools/`, and logged `tool_pruned`.

On 2026-11-04, `ASabale/agent-toolkit@d09087a` left `unused_tools` empty until `state/events.jsonl` had at least 50 `run_ok` or `run_error` events. Below that threshold `evolve_report` set `unused_reason` to `insufficient_telemetry` and included a telemetry object with `events`, `run_events`, and `first_ts`. `tk prune --unused` and `tk prune --unused --dry-run` exited 2 with error `insufficient_telemetry`. A tool whose file mtime was after the first `run_ok`/`run_error` timestamp was never listed as unused. Explicit `tk prune <name>` still archived that name.
