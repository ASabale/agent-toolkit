# Catalog and check

On 2026-11-03, `ASabale/agent-toolkit@9d469d7` added `lib/catalog.py` (530 lines in that commit). `CODING_STANDARDS.md` at the same commit named this module the discovery, indexing, and validation seam. ## Index

On 2026-11-03, `parse_tool_header` at `ASabale/agent-toolkit@9d469d7` read the leading `# @tk-*` comment block and returned a dict with `kind: "tool"`, `name`, `summary`, `safety`, `args`, `output`, `example`, `verified`, and `path`. Each `@tk-arg` line split on `|` into flag, required-or-optional, type (`string`, `int`, `float`, `bool`), and description. A parenthetical `(default: X)` in the description became `default`. The env var was `TK_ARG_` plus the flag with the leading dashes removed, hyphens turned into underscores, and the remainder uppercased.

On 2026-11-03, `load_chain` at the same commit read `chains/<name>.json` and normalized `kind: "chain"` with `name`, `summary`, `safety`, `args`, `steps`, `output`, `example`, `verified`, and `path`.

On 2026-11-03, `discover_catalog` scanned `root_dir/tools` recursively, skipped path parts starting with `.` or `__`, and scanned `root_dir/chains/*.json`. Keys were item names (or a relative path / filename when the name was empty), and the returned dict was sorted by key. An unexpected failure returned whatever items had already been collected, still sorted.

## Find ranking

On 2026-11-03, `find_items` at `ASabale/agent-toolkit@9d469d7` returned every item sorted by name when the query was empty. A non-empty query scored tokens against the name (exact name or name segment: 5; substring: 3), the summary (2), and arg flags plus descriptions (1). Matches sorted by descending score, then name. Zero-score items were omitted. `format_find_output` emitted the two-line shape required by [0002](../decisions/0002-minimum-cognitive-load-and-tokens.md). `format_info_output` printed name, kind, safety, summary, args, output, example, and verified.

On 2026-11-03, `tk` `_cmd_find` called this formatter and, when the formatted text was empty, called `log_event` with `search_miss`. See [Evolver and quarantine](evolver-and-quarantine.md).

## Check

On 2026-11-03, `check_item` at `ASabale/agent-toolkit@9d469d7` returned `{"name", "ok", "errors"}`. For tools it required the file to exist and to be executable, required header fields `name`, `summary`, `safety` in `{read-only, mutating, destructive}`, `output`, `example`, and `verified`, required the example to start with `tk run <name>` and to include every required flag, ran `bash -n` for a bash/sh shebang or `py_compile` for a Python shebang, and ran the file with `TK_DRY_RUN=1` plus dummy required values (`example`, `1`, or `true`). The dry-run had to exit 0 and print JSON on stdout. Other shebangs failed as unsupported. For chains, every step `tool` had to exist in `discover_catalog`. `check_all` aggregated `check_item` over the catalog into `{ok, checked, results, errors}`.

## Python tool SDK

On 2026-11-04, `ASabale/agent-toolkit@0fb0095` added `lib/tool_sdk.py` (104 lines in that commit) and a Python example in the `TK_PYTHON_EXAMPLE` heredoc of `tools/.template`. `discover_catalog` still skips that template because its name starts with `.`. The module imports only the standard library (`json`, `os`, `signal`, `subprocess`, `sys`, `pathlib`). Tests in that commit keep the file at or under 110 lines. Python tools may import it; no catalog tool was rewritten to do so. The example inserts the repo root with `sys.path.insert(0, str(Path(__file__).resolve().parents[2]))`, which assumes the tool file lives at `tools/<ns>/<file>.py`. The tool stays a single file, and the `# @tk-*` header remains the manifest.

On 2026-11-04, the public helpers at `ASabale/agent-toolkit@0fb0095` were `emit`, `fail`, `is_dry_run`, `dry_run_ok`, `dry_run_plan`, `arg_str`, `arg_int`, `paginate`, `run_cmd`, and `run_main`. `emit` writes one compact JSON line (`separators=(",", ":")`) to stdout when `code` is 0 and to stderr otherwise, and returns `code`. `fail` sends `{"error", "why", "fix"}` through `emit` (default code 1). `is_dry_run` is true only when `TK_DRY_RUN` is `"1"` (missing is treated as `"0"`). `dry_run_ok(**fields)` emits `{"dry_run": true, ...fields}` on stdout. `dry_run_plan(plan, **fields)` emits `{"dry_run": true, "plan": plan, ...fields}` on stdout. `arg_str` reads `TK_ARG_<NAME>`: a name that already starts with `TK_ARG_` is used as-is; otherwise leading dashes are stripped, `-` becomes `_`, the rest is uppercased, and `TK_ARG_` is prefixed. An unset or empty value returns the default (`""` when omitted). `arg_int` uses that same env name, falls back to `str(default)` when unset or empty, and exits 2 with `error` `invalid_flag` when the value is not an int (`why`: `<label> is not an int: <raw>`) or is below `min_val` (default 1; `why`: `<label> must be >= <min_val>`). The label drops a leading `-` and a `TK_ARG_` prefix, turns `_` into `-`, and is lowercased. `paginate` copies `items`, keeps `[:max(0, int(limit))]` under `key` (default `"items"`), and always sets integer `count` to the kept length and integer `truncated` to `max(0, len(items) - int(limit))`. `run_cmd` starts the child with `start_new_session=True`, capturing stdout and stderr (default timeout 30). A missing executable exits 1 with `not_found`. On timeout it kills the child process group with `SIGKILL` and exits 1 with `timeout` and `why` `command timed out after <timeout>s`. A non-zero exit exits 1 with `error` set to the `error_code` argument (default `cmd_failed`) and `why` from stripped stderr, else stdout, else `exited <code>`. When the executable name is `gh` and that `why` contains `auth login`, `not logged`, `not authenticated`, `http 401`, or `bad credentials` (case-insensitive), `fix` is `gh auth login`. Success returns `subprocess.CompletedProcess`. `run_main(fn, default_fix=...)` exits with the int `fn()` returns. A `SystemExit` from `fn` (including `arg_int`'s code 2) propagates. `FileNotFoundError` becomes `not_found`, `subprocess.TimeoutExpired` becomes `timeout` (`why` includes the timeout), and any other `Exception` becomes `internal_error` with `why` `str(exc)`. Those three use `default_fix` and exit 1.

## http.json-get

On 2026-11-03, `ASabale/agent-toolkit@429739b` (squash commit for `#97`, pull request `#122`) taught `tools/http/json-get` dotted `--keys` paths. `--keys` is a comma-separated list of paths (default `all`). Each path is split on `.`. A top-level name is copied as-is. A nested path such as `user.name` is kept only when every segment exists, and the result rebuilds that nesting (`{"user": {"name": ...}}`). A missing path is omitted. `all` keeps the decoded document before the byte cap. A JSON array of objects applies the same paths to each object.

On 2026-11-04 this command returned `{"owner":{"login":"ASabale"}}` from `origin/main` at `ASabale/agent-toolkit@0861f7f`:

```
tk run http.json-get --url https://api.github.com/repos/ASabale/agent-toolkit --keys owner.login
```

On 2026-11-03, `ASabale/agent-toolkit@429739b` also set the tool's default output cap to 2048 bytes. The flag is `--max-bytes` (optional int, default 2048). The tool measures compact JSON (`separators=(",", ":")`). A selection larger than the cap is reduced and returned with `truncated`, `fix`, and `hint` instead of the full selection. Pass `--max-bytes <n>` with an integer `n >= 0` to change that cap. `lib/runner.py` `run_tool` applies a second cap, `TK_MAX_OUTPUT_BYTES` (default 65536). Stdout over that limit fails with `error` `output_too_large`. Set `TK_MAX_OUTPUT_BYTES` to at least the compact size to let a larger payload through the runner. When a repair would exceed the runner cap, `fix` and `hint` prefix `TK_MAX_OUTPUT_BYTES=<size>`.

On 2026-11-04, `ASabale/agent-toolkit@3611c65` landed `#139` (pull request `#155`). The full-document escape hatch implemented there is `--max-bytes 0`. With `--keys all` (or omitted), that flag returns the decoded document with no tool-side truncation. With other `--keys`, it returns the path projection with no tool-side truncation. The header at that commit reads: `--max-bytes | optional | int | Output byte cap; 0 returns the full document (default: 2048)`. A truncated payload's `hint` is the same URL with `--max-bytes 0`, and repair `fix` lines keep the caller's `--keys`. The runner cap still applies, so a document larger than 65536 compact bytes also needs `TK_MAX_OUTPUT_BYTES` raised to that size.
